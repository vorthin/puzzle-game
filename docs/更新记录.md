## v2.3 · 2026-09-30 —— 新增可走动 RPG 试玩版《小小社区帮手》

### 玩法和学习目标

- 12×8 的离线小社区地图：孩子可用方向键/遥控器方向键、手机虚拟方向盘控制角色逐格行走，也可点地图上的人物和物品，让角色沿可走道路过去。树丛和池塘挡路，靠近目标后才能交谈或使用。
- 小园丁任务：问小兔花出了什么问题；可以先看花或先拿水壶；观察干湿并尝试解释；浇水后花从垂头变成开花；最后回去告诉小兔。练观察、前因后果与生活步骤。
- 小邮递员任务：听邮递员说目标门牌；拿包裹、辨认星星与圆圈、到正确的房子投递、回访邮递员。练听取线索、图形辨认、空间寻路与主动问路。
- 小园丁/小邮递员各发对应的贴纸，而不是随机抽另一种职业；错误推测或走错房子只会得到线索，不扣分、不重置。每句线索都可以点「再听一次」，不用靠识字过关。

**为什么做成真正走动**：原有游戏主要是从静止的选项里找答案；走到居民身边、绕过障碍、发现道具、回访看结果，孩子经历的是完整的帮助过程，而不是换皮的选择题。两条任务可任选先后顺序，但各自保留行动前后因果。

### 技术取舍和可靠性

- 小地图由 DOM 网格绘制，角色以 CSS 过渡逐格走路；点击目标用广度优先搜索寻路。这一版无需图片素材或外部依赖，双击 `index.html` 离线就能试玩，且地图与碰撞共享同一组坐标，不会出现视觉上有树却可以穿树的问题。
- 当前是玩法原型，场景与人物使用 emoji / CSS，而不是承诺有逐帧像素动画、滚屏大地图或存档中的剧情进度。希望先验证孩子愿不愿意“自己走过去帮邻居”，再决定是否值得制作角色与场景素材。
- 任务剧情不用 `api.rounds()`：先拿水壶或先观察、先做园丁或先送信都合法，强行排成一列会使角色扮演重新变成答题。退出/重玩时注销按键监听、停止长按与自动行走；贴纸仍用共享 `Store`，不影响已有存档。
- 当家长设定的游戏时间到时，行走与互动停止；对话通过现有 `SpeechManager`。语音可开启并重复播放线索；若家长关闭语音或设备不支持朗读，目前只能看文字与图标，需要家长伴读，这是离线试玩版的已知限制。

### 验证

`node _smoke_test.js`：**68 通过，0 失败**（包含两条任务完整通关与可交换行动顺序、障碍、方向键/虚拟方向盘移动、遥控器选项焦点、圆圈误投反馈、任务对应贴纸及重复游玩去重、退出清理与页面脚本/样式引入顺序）。还用 Edge DOM 验证了桌面、常见手机、小屏竖屏与矮横屏布局和实际点击小兔的交互；真实手机/电视的手感仍应试玩确认。

## v2.2 · 2026-09-30 —— 丰富《光之小卫士》的关卡内部玩法

### 1. 发现的问题

《光之小卫士》虽然有三个入口，但原来的每关基本都是「完成一个题目就结束」：
配对一组、数一次、按一次深呼吸。主题有了，任务感还不够，孩子重玩时也容易觉得
只是换了一批 emoji。

这次没有再增加第四个入口。原因是低龄孩子需要稳定的选择结构；把三关内部做成
连续的小任务，既保留熟悉感，又能提供「我正在完成一项任务」的成长感，审核也能
更清楚地逐项检查每个玩法。

### 2. 变身配对：从一波变成多波净化

- 难度 1/2：连续净化 2 波；难度 3：连续净化 3 波。
- 每波重新抽取并打乱能量兽，仍然保留 3-4 只的可控操作量。
- 完成一波会更新「净化波次」星点，短暂过场后进入下一波。
- 配对成功的灰兽和伙伴会禁用，避免重复点击造成重复计数。

**为什么这样改**：单波配对只能练一次对应关系；多波会练到重复识别、视觉扫描和
持续注意力。每波重新洗牌是为了让孩子不能只记位置，必须真的看图配对。没有增加
拖拽要求，继续使用点选方式，因为项目已有颜色配对负责拖拽，而点选更适合电视遥控器。

### 3. 光线数数：从单纯数数变成数量 + 比较

- 每一题仍有「数光线选数字」，但难度 2/3 会交替出现左右两组光线。
- 比较题要求选择「左边更多 / 一样多 / 右边更多」。
- 每局包含 `2 + 难度` 个小任务，进度以星点显示。
- 数量、干扰选项和左右相等的概率都会变化，重玩不会固定答案。

**为什么这样改**：只选一个数字容易变成机械点按；「更多/一样多」是更基础、也更
贴近生活的数学概念。把比较题放在第二档之后，是为了先建立数量对应，再引入关系比较，
避免 3 岁孩子一进来就被抽象的左右关系卡住。

### 4. 能量灯呼吸：从重复按钮变成可见的平静进度

- 难度 1/2/3 分别完成 3/4/5 轮呼吸。
- 每完成一轮点亮一颗星星，全部点亮后才通关。
- 吸气和呼气仍保持舒适的 2.6 秒节奏；难度只增加轮数，**不加快呼吸**。
- 呼吸动画时按钮锁定，防止连续点按把状态机打乱；吸气/呼气分别有语音引导（录音未提供时由浏览器朗读）。

**为什么这样改**：呼吸关的目标是自我调节，不应该用更快速度制造压力。星星进度让
孩子知道还剩几轮，也把「按按钮」变成「完成一次呼吸并点亮一颗星」。

### 5. 可靠性和兼容性

- `config.js` 增加 `levelInfo`，关卡标题提示和呼吸节奏集中配置，换主题时不用改玩法逻辑。
- `levels.js` 的延迟过场都通过 `alive(stage)` 检查，退出后不再写入卸载的 DOM；关卡结束或回内部首页时也主动卸载旧舞台，避免延迟中的呼吸任务继续运行。
- `LG_Game.stop()` 会停止本游戏计时、音频和旧关卡回调；平台回首页时显式调用，避免
  回到首页后旧游戏突然弹出下一关。
- `window.LG_Store` 显式暴露，修复声音开关只改设置界面、实际语音仍播放的问题。
- 保持 `lg_` 存档前缀和原有 `LG_Store` 接口，旧的年龄、时长、贴纸、难度数据继续可读。
- 当前仓库没有 `assets/voice/` 录音素材：`VoiceManager` 在录音不可用时先用 `SpeechManager` 中文朗读题目，不支持朗读时再退回提示音。理由是 3-6 岁孩子不识字，只有音调而没有指令会让比较和呼吸玩法无法理解；家长关闭声音时仍保持静音。新增比较题和呼吸吸/呼气各自的录音 key，日后放入 mp3 就能自动替换朗读。
- 高难度四对配对在矮屏容易把首行挤出视口：游玩屏改为从顶部排列、可滚动，并在小屏收紧按钮和任务间距，避免看不到第一只伙伴。
- 呼吸灯的 CSS 变量提供最小 DOM stub 回退赋值，保证测试环境和旧 WebView 不因样式 API 缺失白屏。

### 6. 验证结果

`node _smoke_test.js`：**53 通过，0 失败**。
新增覆盖：关卡提示与进度条、三关构建及实际多题通关（含普通数数/比较题及一样多分支）、声音关闭及缺录音时中文朗读；DOM 桩还补上了 `innerHTML` 清空子元素的行为，防止把上一题错当成当前题。

## v2.1 · 2026-09-30 —— 首页卡片改为 3/4 列，避免新增游戏后必须下拉

### 1. 发现的问题

v2 新增到 8 个游戏后，首页仍是 2 列布局：8 张卡片会变成 4 行。
首页页面和 `body` 都采用了固定视口布局，原来的方案只能把 `.grid` 设成
`overflow-y: auto`，结果是孩子必须向下滚动才能看到最后一排；在电视遥控器、
平板和低龄孩子使用场景下，这不是理想交互。

### 2. 这次怎么改

- 宽屏默认 **4 列**：8 个游戏正好两行，首页第一眼可以看全。
- 窄屏（宽度不超过 `700px`）使用 **3 列**：手机仍保持足够大的点击区域，8 个游戏只需三行。
- 横屏且高度较矮时恢复 4 列，并进一步缩小卡片，适配电视横屏和小型平板。
- 卡片高度使用 `clamp()` 和 `vh`，不再用宽度比例把卡片撑得过高；这样横屏宽屏不会出现
  「卡片很宽但四行放不下」的问题。
- 仍保留 `.grid` 的 `max-height` 和滚动作为兜底：未来游戏超过当前容量时不会把页面整体撑破，
  但当前 8 个游戏在常见 3/4 列布局下不需要下拉。
- 删除旧的 `.dense` 分支和 `app.js` 游戏数量判断。布局应该由屏幕尺寸决定，而不是由「当前恰好有几个游戏」决定，
  这样以后增删游戏不会触发布局逻辑分叉。

### 3. 为什么不是固定 4 列

固定 4 列在手机上会让每张卡片变窄，标题和 emoji 的点击目标变小；固定 3 列在电视上又浪费横向空间。
所以选择「宽屏 4 列、窄屏 3 列」，这是在**首页不下拉**和**低龄点击面积**之间的折中，
而不是单纯追求一行放得越多越好。

## v2 · 2026-09-29 —— 补齐「记忆 / 精细动作 / 听觉」三块空白 + 存档下沉到引擎

### 0. 为什么要做这次改动

先做了一次能力盘点。把 5 个已有游戏按「主要训练什么」拆开看：

| 已有游戏 | 训练方向 | 用了什么感官 |
|---|---|---|
| 颜色配对 | 颜色认知 + 拖拽 | 眼 + 手 |
| 找规律 | 逻辑推理 | 眼 |
| 找不同 | 视觉搜索 + 专注 | 眼 |
| 情绪认知 | 情绪认知 + 同理心 | 眼（+ 语音提问）|
| 光之小卫士 | 配对 / 数数 / 呼吸放松 | 眼 + 手 |

结论：**6 类基础能力里，只有 1 类（情绪）被覆盖。**
完全没有的方向是：**工作记忆、精细动作、听觉理解、空间推理、生活自理、大运动**。

3-6 岁是「听觉理解」和「工作记忆」发展最快的阶段，也是幼儿园入学前考察最多的能力，
但一个考「耳朵」的游戏都没有 —— 语音只被用来「念题」，从没被当作「题目本身」。
这是本次要补的第一个、也是最主要的缺口。

另外发现一个**留存问题**：所有游戏都是「出 1 题 → 答对 → 结束」。
孩子点两下就回到首页，单次体验撑不到 2 分钟，且没有任何「下次还想来」的理由。

所以本次做三件事：**补 3 个游戏（补能力缺口）+ 2 个引擎改造（补留存）**。

---

### 1. 🃏 新增 `memory-match.js` —— 翻牌配对

**玩法**：一排盖着的卡片，点开两张，一样的留下，不一样的翻回去。

**为什么选它**：
- 「工作记忆」是这个年龄段最核心、也最难自己练到的能力
- 玩法本身自带难度梯度（牌越多越难），天然适配 3-6 岁跨度
- 零素材：全部用 emoji，不需要任何图片

**关键设计决策：翻开两张不一样的牌「不算答错」**

这一点单独拎出来说，因为它是本项目最容易做错的地方。
游戏里写了：

```javascript
} else {
  // 不一样：翻回去。这不是「答错」，不调 r.retry()。
  api.sound.soft();
  api.speak('再找找看');
```

如果这里调 `r.retry()`，孩子翻开两张不一样的牌就会被记一次「连错」，
连错两次难度直接降到 1 —— 而翻牌游戏里翻开两张不一样是**必经的正常操作**。
用难度系统去惩罚一个正常玩法，是把「自适应难度」用反了。
所以：**只有「真的选错了目标」才算答错**，`shadow-match` 的拖错影子、
`listen-do` 的点错物品才算。

`shadow-match.js` 和 `listen-do.js` 里都写了同样的注释说明，
避免后续维护时改错。

**另一个决策：牌面逐副变大**

一局 3 副牌，第 1 副 3 对、第 2 副 4 对……上限 6 对。
单次时长从原来的 ~1 分钟延长到 3-5 分钟，且**难度是自然上升的**，
不需要在中间弹「要不要继续」，孩子不会感到突兀。

### 2. 🐾 新增 `shadow-match.js` —— 影子配对

**玩法**：彩色小动物拖到自己的黑色影子上。

**为什么选它**：
- 训练「视觉辨别 + 空间对应」，是 3-6 岁空间认知的入门任务
- 补上「精细动作」（拖拽对 3 岁孩子手眼协调要求高）

**关键实现决策：用 CSS `brightness(0)` 做影子，零图片**

```javascript
.sh-shadow { font-size: 8vh; filter: brightness(0) opacity(.75); }
```

`brightness(0)` 能把任意彩色 emoji 变成纯黑剪影。
也就是说 **影子 = 同一个 emoji + 变黑**。

取舍说明：真实的影子应该和原图轮廓一致，emoji 变黑后细节（眼睛、条纹）会丢失，
所以这个玩法严格说更接近「找同一个东西的黑色版本」。
但考虑到项目要求**纯离线、零素材、不能联网下载图片**，
这已经是最优解 —— 真实影子需要准备 4-5 张剪影 PNG。
如果以后愿意加素材，只需把 `.sh-shadow` 里的 emoji 换成 `<img src="assets/xxx.png">`，逻辑不用动。

**难度分级用「长得像的动物」而不是「数量」**

```javascript
const EASY     = ['🦁', '🐰', '🐢', '🐬'];      // 差别很大
const SIMILAR_1= ['🐱', '🐶', '🦊', '🐷'];      // 有点像了
const SIMILAR_2= ['🐭', '🐹', '🐨', '🦡'];      // 更像
```

只加数量的话，孩子数一数就能全对，难度是「假」的。
换成相似动物后，3 岁孩子（用 EASY）和 5 岁孩子（用 SIMILAR_2）
做的是同一个玩法但难度真实不同。

### 3. 👂 新增 `listen-do.js` —— 听指令

**玩法**：语音说「先摸红色的苹果，再摸星星」，孩子必须**按顺序**点。

**为什么选它**：
- 这是本次最重要的补充：现有游戏全部只考「眼睛」
- 「听完一串话照着做」= 听觉工作记忆 + 执行功能，
  是幼儿园大班入学的典型考察项
- 语音朗读功能引擎里本来就有（`SpeechManager`），**零新增成本**

**决策 1：念完才允许判对错**

```javascript
api.speak(txt, arm);   // arm 才会把 ready 置 true
```

如果边念边判，孩子手比声音快，第一下必然点错，然后开始怀疑游戏而不是自己。
`SpeechManager.speak()` 新增了 `onEnd` 回调专门解决这个。

**决策 2：念完再给 2.5 秒记忆期，这期间点了不判错**

3-4 岁孩子听完需要时间把话转成动作。这 2.5 秒里点了只提示「先听清楚哦」，
不计入错误 —— 否则孩子反而会因为「刚听完就点」被扣分。

**决策 3：设备不支持语音时降级成「看图做」**

```javascript
const visual = !api.canSpeak();
```

老安卓、某些电视浏览器没有 `speechSynthesis`。如果不处理，
这个游戏在那些设备上是**完全不能玩**的（题目在语音里，听不到就无从下手）。
降级方案：把指令同时用图标序列显示出来 `🍎 → ⭐`，变成看图排序记忆。
游戏照样能玩完，只是训练重点从「听觉」变成「顺序记忆」。

**决策 4：点错不清空进度**

「再想想」+ 柔和提示音，已完成的步骤保持完成状态。
孩子在 4 步指令的第 3 步卡住时，不该被罚回原点。

### 4. ✨ 新增 `js/engine/Store.js` —— 存档层下沉到引擎

**改之前的问题**：

`light-guardian/store.js` 里有一份完整实现：localStorage 读写、贴纸去重、
连对升难/连错降难、今日分钟。但它是**光之小卫士私有的**。
新游戏想存一点东西（比如难度），只能照抄一遍。抄出来的第二份和第一份迟早会不一致 ——
这是所有「复制粘贴做抽象」的通病。

**改之后**：`Store.create('前缀')` 建一份带命名空间的存档，能力三件套：

| 能力 | 用途 |
|---|---|
| `get / set / del` | 命名空间隔离，不同游戏不会互相覆盖键 |
| `reportCorrect / reportWrong` | 连对升难 / 连错降难，**永不低于 min** |
| `grantNewSticker` | 发贴纸，**优先发没拿过的**，全齐了才重复 |

**兼容性是怎么保证的**：

`LG_Store` 被重写成**只有一层适配**，对外接口（`get` / `set` / `getStickers` /
`grantNewSticker` / `getLevel` / `reportCorrect` / `reportWrong` …）**一个都没变**，
键名仍然是 `lg_difficulty` / `lg_stickers` / `lg_todayMinutes`。
`light-guardian` 的其余 4 个文件**一行都不用改**。
→ 已有存档直接接着用，不需要数据迁移，也不会把孩子已有的贴纸清空。

冒烟测试里专门加了这条断言守住它：

```javascript
ok('LG_Store 仍写 lg_ 前缀', store['lg_difficulty'] === '1');
```

**额外做的两件小事**：
- 所有 `localStorage` 调用包了 `try/catch` 并降级到内存。隐私模式下
  `setItem` 会抛 `QuotaExceededError`，原来的代码会让整页白屏
- `get()` 遇到坏 JSON 不抛错，退回原始字符串（原来也是这样，保持一致）

### 5. ✨ `api.rounds()` —— 多关卡循环收进引擎

**改之前的问题**：所有游戏都是「出 1 题 → 答对 → 结束」。
这个问题写在每个游戏里都是重复代码，而且低年级游戏出题逻辑本身就很短，
出题代码比循环代码还短，很不合理。

**改之后**：

```javascript
const r = api.rounds(stage, {
  total: 5,                        // 本次玩几关
  scope: 'mm',                     // 存档命名空间
  stickers: MM_STICKERS,           // 本游戏的贴纸册
  draw(host, no) { /* 画第 no 关 */ },
  onWin(res) { /* 全部通关 */ },
});
// 答对 → r.next()      答错 → r.retry()
```

引擎接管了：进度点渲染、出下一关的间隔、通关发贴纸、难度记录、
以及**退出游戏后不再继续出题**（`host.isConnected` 检查，避免玩家已经回首页了
定时器还在往一个已卸载的 DOM 里塞东西）。

**踩过的坑（已修）**：第一版 `makeRounds` 在 return 之前同步调了 `draw()`，
而游戏里写的是 `const r = api.rounds(...)`，`r` 还没赋值就有了暂时性死区，
`draw` 里读 `r.store` 直接抛 `Cannot access 'r' before initialization`。
**三个新游戏全部白屏。** 冒烟测试当场抓到，改成 `setTimeout(draw, 0)` 延后一拍解决。
这条记录留在代码注释和 `GameManager.js` 里了。

**向后兼容**：现有 4 个游戏仍然走原来的 `api.reward()` 单题模式，
`rounds()` 是纯新增 API，一个字没改它们的行为。

### 6. ✨ 首页贴纸墙（🏅）

**为什么加这个**：

上面 3 个游戏各自发贴纸，但如果贴纸发完就没人再看，收集就失去意义。
把它提到首页做成一个入口，孩子每次回来都能看到「我又多了 2 张」，
这是**唯一能让「玩得多」变成「还想玩」的正反馈闭环**。

**为什么不发金币/钻石**：无限货币在儿童应用里没有正反馈价值，
（这是「光之小卫士」需求第 7 条定的调子：贴纸是有限的、可收集的、有仪式感的）。

**数据来源**：各游戏在**模块顶层**（不是 `start()` 里）调
`Store.wall.register()` 上报自己的贴纸册。
放外面是因为孩子第一次点进游戏之前，贴纸墙就该是完整的。
`owned` 传的是**函数**而不是数组，墙渲染时才去读存档，避免读到过期副本。

没拿到的显示 ❔ 而不是剧透图案 —— 收集的乐趣在「发现」，不在「看图鉴」。

### 7. 🗣️ `SpeechManager.speak()` 支持 `onEnd` 回调

**为什么**：`listen-do` 需要「念完了再让孩子操作」。
原来的 `speak()` 是发完就不管了（fire-and-forget），拿不到结束时机。

**为什么必须有兜底**：部分设备/浏览器**不触发** `onend` 事件。
如果只依赖 `onend`，听指令会永远停在准备期不动 = 看起来卡死。
所以加了 `1200ms + 字数 × 220ms` 的超时兜底，保证 `onEnd` **一定会被调用一次**。
「一定会被调用」比「通常会被调用」重要得多。

**向后兼容**：第二参数可选。现有全部调用（`api.speak('...')`）行为完全不变。

另外导出了 `SpeechManager.supported()`，供 `api.canSpeak()` 判断是否要降级。

## 刻意没做的事

写下来是为了让审核时知道这些不是遗漏，而是有意的：

1. **没给现有 4 个游戏套 `rounds()`** —— 它们都是单题逻辑，套上要重写玩法逻辑。
   本次只保证 `rounds()` 可用，改不改由每个游戏自己决定。
2. **没做「分类收纳 / 谁多谁少 / 描线 / 滑块拼图 / 安全小卫士」** ——
   这些是第一梯队的其它候选，但一次加太多会让 diff 无法审阅。
   建议下一批做「分类收纳 + 描线」，正好补精细动作和数学前概念。
3. **没引入 build 工具 / 框架 / 第三方库** —— 项目要求双击 `index.html` 就能跑。
   加任何依赖都会破坏这个前提。
4. **没做云同步 / 排行榜 / 广告** —— 需求里明令禁止，且涉及儿童隐私。
5. **没改 `light-guardian` 的 4 个文件** —— 只改了 `store.js`（重写成适配层）。
   它是本项目最完整、最花心思的一个游戏，稳定性优先，**尽量不碰**。
6. **没动 `TimerManager` / `RewardManager` / `AudioManager`** —— 现有实现没问题，
   本次新增能力不依赖对它们的修改。
7. **贴纸墙没做「家长可见的清空/导出」** —— 属于加分项，不在本次范围。
   如果孩子贴纸存满了想重置，需要另开一轮加。
